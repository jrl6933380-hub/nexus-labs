Pod Room now displays the last 500 inference attempts recorded in Redis. Normal Nex pod calls, pod assistant calls, individual build/edit rounds, and the direct Test Nex action are measured. This includes owner calls without charging the owner. Refresh Pod Room after a test run to see the updated summary.

Records contain only task kind, timestamps, duration, success, first-token timing when available, and reported input/output/cached/reasoning token counts. They contain no account identities, prompts, responses, tool arguments, or credentials. Storage uses the existing Redis credentials, retains at most 500 records, and expires after 30 days without new measurements. The report is served by the existing owner-authenticated pod-controller endpoint; customer accounts cannot read it.

First-token timing includes the HTTP wait plus time to the first content or reasoning delta in a build stream. Request durations include queueing and inference. The output rate is tokens divided by the whole request duration, not decode-only speed. Missing token counters are excluded from token-based calibration rather than replaced with reservation estimates. Each retry and continuation round is recorded independently; failed attempts are counted separately. Records are best effort; a Redis outage does not prevent a reply or change billing.

Run a mix of short chat, long chat, Life requests, fresh builds, edits, and team work. Compare typical and slow request durations and reported token counts with the actual GPU and hourly rate already shown in Pod Room. Allowances still use the policy in measured-ai-usage.md; this change collects evidence and does not automatically change limits or claim a final capacity estimate.

These application measurements do not measure GPU utilization, GPU memory, decode-only speed, global concurrent requests, or idle pod uptime. Those require runtime metrics and a controlled concurrency trial before projecting total customers or hourly capacity. No live pod benchmark was performed as part of this change.
